# Kaggle GPU Runner

Ноутбук, который поднимает RFC 0022 Runner на Kaggle с GPU. Нужен там, где
модель не прогнать локально: на ARM-хостах кластера (rpi5/orangepi) страница
через CPU — минуты, абзац перевода — три минуты на rpi5 и девять на orangepi.
На T4 абзац переводится за ~10 с.

```
colab/kaggle-runner/
  runner.ipynb           обёртка: окружение, туннель, запуск
  kernel-metadata.json   метаданные для `kaggle kernels push`
  README.md              короткая памятка
```

Раннер — **один процесс с одной моделью** (Qwen2.5-VL-7B, 15 000 из 16 384 МБ
на T4). Она обслуживает все задачи: `ocr`, `vision`, `table`, `formula`,
`refine`, `translate`. Второй модели рядом нет места.

## Логика живёт в репозитории, не в блокноте

Блокнот клонирует BookAssembler из `main` на GitHub и запускает
`python -m src.agents.runner`. Всё поведение — в `src/agents/runner/`:

| Что | Где |
|---|---|
| HTTP-эндпоинты | `src/agents/runner/app.py` |
| Очередь генераций, пул моделей | `src/agents/runner/pool.py` |
| Выход по простою | `src/agents/runner/idle.py` |
| Объявление Manager'у | `src/agents/runner/announce.py` |
| Загрузчики моделей | `src/agents/runner/loaders/` |

Следствие: **правка раннера вступает в силу только после push в `main` и
нового запуска блокнота.** Раннер, запущенный до push, работает на старом
коде, сколько бы он ещё ни жил.

## Запуск и перезапуск — по шагам

1. **Push.** Правки раннера должны быть в `origin/main`.
2. **Новая сессия.** В Kaggle — *Stop session*, затем *Run All*. Не
   перезапускать одну последнюю ячейку: старый процесс раннера держит порт, а
   код он взял при прошлом клоне. Новая сессия даёт чистый диск и новый туннель.
   (Ячейка 1 и сама удаляет прежнюю копию репозитория перед клоном.)
3. **Адрес.** В выводе ячейки 4 — строка
   `Runner will announce as: https://<слова>.trycloudflare.com`. Адрес
   меняется при каждом новом туннеле.
4. **Готовность.** Ячейка 5 работает бесконечно — это нормально, это сам
   раннер. Он готов, когда `/health` отвечает `"ready": true` (загрузка модели —
   пара минут).
5. **Подключение к движку** — см. ниже.
6. **Проверка, что поднялся новый код** — см. «Проверка».

Раннер **выходит сам после 15 минут простоя** (`KAE_RUNNER_IDLE_TIMEOUT`):
для следующей работы снова шаги 2–5. Если он ушёл посреди перевода книги,
перевод продолжится на краевом кластере, сделанное не теряется
(`src/assembler/translator.py`).

## Подключение к движку

Движок ходит в раннер напрямую, через туннель (Manager из RFC 0022 здесь не
нужен). Агент описан в `agents.json` движка — на rpi5 это
`/data/kae/agents.json` (в контейнере `/data/ssd/agents.json`) или менеджер
агентов в редакторе:

```json
{
  "name": "Kaggle Multi",
  "host": "https://<слова>.trycloudflare.com",
  "active_model": "Qwen2.5-VL-7B-Instruct",
  "kind": "multimodel",
  "roles": ["formula", "ocr", "refine", "table", "translate", "vision"],
  "token": "<KAE_RUNNER_TOKEN>"
}
```

- `host` — адрес из шага 3, **без** `/` в конце.
- `roles` — все задачи раннера. Без `translate` перевод на GPU не пойдёт,
  без `refine` уточнение останется на CPU.
- **Этот агент — первым в списке.** Роль достаётся первому доступному агенту
  в порядке файла: если выше стоит ollama с той же ролью, работа уйдёт на CPU.
- Анализаторы выбирают агента при старте своего шага. Документ, обработка
  которого началась до подключения раннера, его не увидит — загрузить заново.

## Проверка

```bash
RUNNER_URL=https://<слова>.trycloudflare.com

curl -s $RUNNER_URL/health
# {"status":"ok","kind":"runner","tasks":[...],"models_loaded":["Qwen2.5-VL-7B-Instruct"],"ready":true}

curl -s $RUNNER_URL/metrics | grep -E 'up_seconds|infer_total'
# kae_runner_up_seconds — секунды с запуска: после перезапуска маленькое
```

Новый ли это код (с `2a4be89`): лимит длины ответа должен быть положительным,
и новый раннер отклоняет `0` с кодом 422; старый его молча принимает.

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST $RUNNER_URL/infer \
  -H "Authorization: Bearer $KAE_RUNNER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"task":"translate","prompt":"x","max_new_tokens":0}'
# 422 — новый код; 200 — старый, перезапустить (шаг 2)
```

## Как раннер берёт работу

- **Одна генерация за раз.** Запросы ждут очереди; `/health` и `/metrics`
  отвечают и во время генерации. Без очереди несколько `model.generate` на
  одной T4 шли бок о бок, и «Programming the Z80» простоял семь минут без
  единого ответа.
- **Потолок ответа.** `/infer` принимает `max_new_tokens` (не больше 2048 —
  потолка загрузчика). Разметка страницы и перевод просят до 1536: жадное
  декодирование, начавшее повторяться, иначе идёт до 2048 — минуты на T4.
- **Ушедший клиент.** Если клиент отвалился по таймауту, пока его запрос
  стоял в очереди, запрос не генерируется (ответ 499, в ошибки не идёт).
- **Таймауты движка** рассчитаны на очередь: общий `KAE_INFER_TIMEOUT` —
  240 с, OCR — 300 с. Перевод на GPU по таймауту не повторяет запрос —
  единицу возвращает в очередь само задание.

## Контракт

`POST /infer` — `{"task": "vision", "image_b64": "…", "prompt": "…",
"max_new_tokens": 1536}` → `{"text": "…"}` (RFC 0022 §4.2, §4.4). Текстовые
задачи (`refine`, `translate`) несут `prompt` без картинки. Раннер модель
только исполняет; страницу рендерит и присылает вызывающая сторона.

Замер на Qwen2.5-VL: страница 512 px отвечает за ~1.7 с, 900 px не ответила за
180 с. Стоимость растёт с числом визуальных токенов, а передача 8 КБ при
~300 КБ/с занимает миллисекунды — то есть ограничивает GPU, не канал. Размер
картинки задаётся на стороне KAE (`KAE_VISION_DPI`, `_JPEG_QUALITY`,
`_MAX_DIM`) и поднимается только против замера на целевой карте.

## Запуск из терминала вместо UI

```bash
export KAE_MANAGER_URL=https://your-manager
export KAE_RUNNER_TOKEN=...
bin/push-kaggle-runner.sh      # подставит секреты и сделает push блокнота
bin/poll-kaggle-runner.sh      # дождётся, пока kernel перейдёт в RUNNING
```

Скрипт подставляет секреты вместо плейсхолдеров на push-time, поэтому в git
они не попадают. При ручном запуске в UI значения читаются из Kaggle Secrets
(`KAE_MANAGER_URL`, `KAE_RUNNER_TOKEN`). Правка самого блокнота
(`runner.ipynb`) доходит до Kaggle только этим push'ем или ручной правкой в UI.

## Переменные окружения

| Переменная | Где | Что делает |
|---|---|---|
| `KAE_RUNNER_LOADERS` | блокнот, `qwen_vl` | какие загрузчики регистрировать |
| `KAE_RUNNER_IDLE_TIMEOUT` | блокнот, `900` | секунд простоя до выхода |
| `KAE_INFER_TIMEOUT` | движок, `240` | сколько движок ждёт ответа раннера |
| `KAE_PAGE_CLASSIFY_MAX_TOKENS` | движок, `1536` | потолок ответа разметки страницы |
| `KAE_TRANSLATE_MAX_TOKENS` | движок, `1536` | потолок ответа перевода |
