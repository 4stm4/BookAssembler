## Вторник 26.08 — Семантические декораторы (P2.1)

**Почему:** математический/учебный текст сейчас неотличим от прозы;
`DefinitionSpec` объявлен, но не создаётся. Расширяем `SemanticUnit` до
5 подтипов и пишем эвристические детекторы.

### Задачи
1. **Модели** в `src/krm/models.py`:
   - `TheoremSpec(name, number, statement_id, kind)` — kind ∈
     {theorem, lemma, proposition, corollary, axiom, postulate}.
   - `ProofSpec(target_theorem_id, is_end_marked)`.
   - `ExampleSpec(number, name)`.
   - `RemarkSpec(number)`.
2. **Активация `DefinitionSpec`** — добавить детектор
   `DefinitionDetectorAnalyzer` (эвристики: «X — это …», «Under
   Y we understand …», курсив термина, префикс «Определение N»).
3. **`TheoremDetectorAnalyzer`**:
   - префиксы «Theorem 1.2» / «Теорема 1.2» / «Lemma …» / «Proposition …»;
   - определение статьи `statement_id` = ссылка на структурный блок
     (следующий `ParagraphBlock`);
   - proof-marker «□», «QED», «∎» — `is_end_marked=True` у ближайшего
     ProofSpec выше.
4. **Регистрация** в pipeline после `HeadingAnalyzer`, до
   `CalloutDetector` (theorem не должен превратиться в callout).
5. **Wire-up**: сериализация app.py, LaTeX-рендер (theorem через
   `amsthm` — добавить в preamble), chunker (theorem/proof/example
   → атомарные), translator (statement/name/definition_text
   переводимы).

### Артефакты
- `src/analyzers/definition_detector.py`, `theorem_detector.py`.
- Тесты: ~20 unit (по 5 на каждый декоратор).
- `src/assembler/latex_builder.py`: `\newtheorem{...}` preamble.

### Exit criteria
- 5 semantic decorators (⚠️ → ✅ в KRM_ENTITIES_MAP).
- ≥ 200 unit-тестов total.
- Smoke: параграф с «Теорема 3.1» → строит `TheoremSpec(kind='theorem',
  number='3.1')`, статья статья попадает в его `statement_id`.

## Среда 27.08 — Расширение Knowledge Graph (P2.2)

**Почему:** сейчас в KG живут только `REGISTER`/`INSTRUCTION`/`HEX`
(3 из 7 объявленных). Историко-техническая литература (PDP-11) без
`Person`/`Organization`/`Product` даёт очень бедный граф.

### Задачи
1. **Расширить `EntityType`** в `src/graph/knowledge_graph.py`:
   `PERSON`, `ORGANIZATION`, `PRODUCT`, `SIGNAL`, `FORMULA_ID`,
   `LOCATION`, `DATE`, `VERSION`, `URL`.
2. **Расширить `RelationType`**: `AUTHORED_BY`, `PUBLISHED_IN`, `CITES`
   (bib → тело), `PART_OF` (иерархия), `VERSION_OF`, `ALIAS_OF`.
3. **Детекторы** — расширить `EntityExtractorAnalyzer` (или новый
   `ProperNounExtractorAnalyzer`):
   - `Person`: заглавная + инициалы (`D. M. Ritchie`, `Кнут Д. Э.`).
   - `Organization`: заглавные аббревиатуры + суффикс Inc./Corp./Ltd./LLC.
   - `Product`: паттерны модели («PDP-11/45», «MC68000», «Intel 8086»).
   - `Date`: год + месяц/день (простой regex + локали).
   - `Version`: `v1.2.3`, `1.0-rc1`.
4. **Связи**:
   - `Person → BibEntryBlock` через `AUTHORED_BY`.
   - `ParagraphBlock → BibEntryBlock` через `CITES` (parse `[N]` в теле).
5. **UI**: обновить `GraphView` (если есть) — новые типы в легенде.

### Артефакты
- `src/analyzers/proper_noun_extractor.py`.
- Расширенный `entity_extractor.py`.
- Тесты: ~15 unit + расширить `test_graph_invariants.py`.

### Exit criteria
- 9 EntityType-типов пишутся, ≥ 5 RelationType пишутся.
- На PDP-11 книге граф вырастает с ~500 nodes до ~1500+ nodes.

## Четверг 28.08 — Служебные типы (P3)

**Почему:** дочистить оставшиеся ❌ в KRM_ENTITIES_MAP.

### Задачи
1. **`EphemeraBlock`** (running headers/footers/page numbers) — явный
   тип. `TitlePageAnalyzer` сейчас автоматически tombstone'ит, но не
   выделяет — переработать: сначала `EphemeraDetectorAnalyzer` строит
   `EphemeraBlock` (kind ∈ header/footer/pagenum), потом
   `is_tombstoned=True` только по конфигу.
2. **`AlgorithmBlock`** (extends `CodeBlock`): нумерованный псевдокод.
   Признак: «Algorithm N: …» + нумерованные строки. LaTeX через
   `algorithmicx` (добавить в preamble).
3. **`SidebarBlock`** (боковой блок): bbox явно вне основной колонки
   (0 < x0 < 0.15 или 0.85 < x1 < 1.0) + непрерывный вертикальный
   диапазон. LaTeX через `wrapfig` или отдельный minipage.
4. **`IndexEntryBlock`**: паттерн «Term, page1, page2» внутри
   `ContainerUnit` с title `Index/Указатель/Предметный указатель`.

### Артефакты
- 4 новых типа + 4 детектора + серии тестов (~20 unit).
- LaTeX-preamble: `algorithmicx`, `wrapfig`.

### Exit criteria
- Все ❌ из KRM_ENTITIES_MAP закрыты (кроме сознательно отложенных).
- ≥ 240 unit-тестов total.

## Пятница 29.08 — Skills Engine MVP (RFC 0006)

**Почему:** самый крупный пробел в P3-приоритетах. Даже минимальный
skeleton развяжет дальнейшую работу с плагинами.

### Задачи
1. **YAML-парсер Skills** (RFC 0006 §3):
   ```yaml
   name: pdp11-instructions
   version: 1.0.0
   apply_when: source.tags contains 'pdp11'
   steps:
     - detect: instruction   # ссылка на InstructionSpec detector
     - normalize: mnemonic
   ```
2. **`SkillsRunner`** — выполняет декларативные шаги через существующий
   `PipelineRunner`; skills = композиция manifested analyzers, без
   произвольного Python (RFC 0006 §inv).
3. **Валидация SemVer** и `apply_when` (простой DSL: `contains`, `==`,
   `in`).
4. **Один готовый pack**: `skills/pdp11.yaml` — instruction detector +
   register normalization.
5. **API endpoint** `/api/v1/skills` — список + применение к документу.

### Артефакты
- `src/skills/{loader,runner,models}.py`.
- `skills/pdp11.yaml`.
- `src/api/app.py`: `/skills` GET/POST.
- Тесты: ~15 unit + один интеграционный.

### Exit criteria
- `pdp11.yaml` можно применить к документу через API.
- Skills никак не позволяют execute arbitrary Python — только composе
  зарегистрированных анализаторов.

### Риск
Skills Engine — большая тема, реалистично успеть только MVP.
Полноценный DSL, sandbox, версионирование — сдвинутся на следующую
неделю.

## Правила автономной работы

1. **Не коммитить без green pytest** на затронутых файлах.
2. **Один подэтап — один коммит.** Если этап оказался больше, чем
   ожидалось, — разбить на подэтапы, не сваливать в один PR.
3. **Каждый день начинать** с `git pull origin main` + `pytest -q`
   для baseline; если что-то красное — сначала fix, потом новый код.
4. **Каждый день заканчивать**:
   - `git push origin main`,
   - обновить `docs/development/logs/YYYY-MM-DD.md` (что сделано,
     что заблокировано, что перенесено),
   - обновить `COMPLIANCE_AUDIT.md` если сдвинулись статусы.
5. **Тупики**: если задача не идёт > 90 мин без прогресса — оформить
   как отдельный `spawn_task` chip и продолжить со следующего пункта
   плана; не блокировать неделю на одном узле.
6. **Правило пользователя `feedback_quality_over_speed`**: если
   встаёт выбор «быстрый костыль vs правильно» — правильно, даже
   если сдвигает день. Отчёт объяснит.
7. **Правило `feedback_no_local_install`**: любой pip/npm/kaggle —
   в Docker или одноразовый venv в scratchpad.
8. **Правило `feedback_check_rfc`**: перед изменением кода — сверка
   с соответствующим RFC (см. карту в `0001-overview.md §4`).
