Недельный план для непрерывной работы с 25 августа на собственном
edge-кластере из трёх ARM-хостов. Каждый день — измеримые артефакты,
exit-critera и буфер под непредвиденное. План опирается на текущее
состояние `main` (`ba92a94`) и три живых карты:
[RFC 0001–0022](../architecture/),
[COMPLIANCE_AUDIT.md](../architecture/COMPLIANCE_AUDIT.md),
[KRM_ENTITIES_MAP.md](../architecture/KRM_ENTITIES_MAP.md).

## Кластер и роли

| Хост | Роль | Что уже стоит | Куда использовать |
|---|---|---|---|
| **rpi5** | primary compute | `kae-engine` (Docker), `kae-manager` + `kae-manager-tunnel`, ollama (llama3.1:8b, qwen2.5:7b, coder-3b/7b, llama3.2:1b) | KAE UI + Manager + ollama refine/translate |
| **orangepi** | secondary compute | osfabricum, pomobill (посторонние), portainer, ollama (llama3.1:8b, qwen2.5:7b) | второй ollama-агент (redundancy) + опциональный vision (LLaVA/Qwen2-VL) |
| **rpi4** | backup deploy | ⚠️ offline на 22.08 — восстановить в понедельник | резервный KAE-инстанс (docker compose) + опциональный Runner для тяжёлых batch-jobs |

**GPU нет ни у одного** — весь inference через ollama на CPU / NPU
(RK3588 на orangepi имеет NPU, но ollama пока не использует). Значит:
- Kaggle GPU-Runner **больше не в основной схеме**, но остаётся как
  **opt-in fallback для vision-задач** (Qwen2.5-VL-7B на 2×T4 работает
  за секунды, на CPU rpi — минуты). Полная автоматизация через
  `kaggle kernels push` + template-подстановка токенов (в git —
  placeholder, реальные значения sed'ятся при push'е из моих env
  vars). Никакого клика в Kaggle UI не требуется.
- Vision-задачи (table/formula/diagram) сначала пробуем через ollama
  vision-модели (`llava:7b`, `qwen2-vl:7b` если доступна) на orangepi;
  fallback — оставляем сырой crop страницы и `needs_vision_ocr=True`
  для ручной обработки.
- Manager+Runner превращается по факту в **Manager-only** + ollama
  как прямой backend. Runner-half сохраняем для тестового окружения.

**Стиль работы:**
- каждый подэтап = отдельный коммит (текущий паттерн, ~180 unit-тестов зелёные);
- «не ставить локально» — только Docker/venv в scratchpad;
- сверяться с соответствующим RFC перед изменениями;
- E2E-проверка на реальной книге (PDP-11) — раз в 2–3 дня;
- push на GitHub через SSH-remote (HTTPS не сконфигурирован).

## Вторник 26.08 — Семантические декораторы (P2.1)

**Почему:** математический/учебный текст сейчас неотличим от прозы;
`DefinitionSpec` объявлен, но не создаётся. Расширяем `SemanticUnit`
до 5 подтипов и пишем эвристические детекторы.

### Задачи
1. **Модели** в `src/krm/models.py`:
   - `TheoremSpec(name, number, statement_id, kind)` — kind ∈
     {theorem, lemma, proposition, corollary, axiom, postulate}.
   - `ProofSpec(target_theorem_id, is_end_marked)`.
   - `ExampleSpec(number, name)`.
   - `RemarkSpec(number)`.
2. **Активация `DefinitionSpec`** — добавить детектор
   `DefinitionDetectorAnalyzer` (эвристики: «X — это …», «Under
   Y we understand …», курсив термина, префикс «Определение N»).
3. **`TheoremDetectorAnalyzer`**:
   - префиксы «Theorem 1.2» / «Теорема 1.2» / «Lemma …» /
     «Proposition …»;
   - `statement_id` = ссылка на следующий `ParagraphBlock`;
   - proof-marker «□», «QED», «∎» — `is_end_marked=True` у ближайшего
     ProofSpec выше.
4. **Регистрация** в pipeline после `HeadingAnalyzer`, до
   `CalloutDetector` (theorem не должен превратиться в callout).
5. **Wire-up**: сериализация app.py, LaTeX-рендер через `amsthm`
   (`\newtheorem{...}` в preamble), chunker (theorem/proof/example →
   атомарные), translator (statement/name/definition_text
   переводимы).

### Артефакты
- `src/analyzers/definition_detector.py`, `theorem_detector.py`.
- Тесты: ~20 unit (по 5 на каждый декоратор).
- `src/assembler/latex_builder.py`: `\newtheorem{...}` preamble.

### Exit criteria
- 5 semantic decorators (⚠️ → ✅ в KRM_ENTITIES_MAP).
- ≥ 200 unit-тестов total.
- Smoke: параграф с «Теорема 3.1» → строит `TheoremSpec(kind='theorem',
  number='3.1')`, статья попадает в его `statement_id`.

   minipage.
4. **`IndexEntryBlock`**: паттерн «Term, page1, page2» внутри
   `ContainerUnit` с title `Index/Указатель/Предметный указатель`.

## Пятница 29.08 — Skills Engine (RFC 0006) — полный DSL

**Почему:** самый крупный пробел в P3-приоритетах. Один день на
парсер + runner + три пакета.

### Задачи
1. **YAML-парсер Skills** (RFC 0006 §3):
   ```yaml
   name: pdp11-instructions
   version: 1.0.0
   apply_when: source.tags contains 'pdp11'
   steps:
     - detect: instruction
     - normalize: mnemonic
   ```
2. **`SkillsRunner`** — выполняет декларативные шаги через
   существующий `PipelineRunner`; skills = композиция manifested
   analyzers, без произвольного Python (RFC 0006 §inv).
3. **`apply_when` DSL**: `contains`, `==`, `in`, `and`, `or`,
   `not`, `matches` (regex), `page_count > N`, `has_language('russian')`.
4. **SemVer совместимость**: skill declares `requires: {kae: '>=0.4.0'}`;
   runner отказывается при mismatch.
5. **Три готовых pack**:
   - `skills/pdp11.yaml` — hardware manuals (register+instruction).
   - `skills/pdf-lit.yaml` — художественная литература (heading +
     para + footnote + bib, без callout/theorem).
   - `skills/math-book.yaml` — theorem/proof/example priority,
     callout отключён (иначе съест «Замечание N»).
6. **API**: `/api/v1/skills` GET (список), POST
   `/api/v1/skills/{name}/activate` (per-document).

### Артефакты
- `src/skills/{loader,runner,models,dsl}.py`.
- `skills/pdp11.yaml`, `skills/pdf-lit.yaml`, `skills/math-book.yaml`.
- `src/api/app.py`: `/skills` endpoints.
- Тесты: ~30 unit + один интеграционный.

### Exit criteria
- Три пакета применяются к разным документам через API.
- Skills никак не позволяют execute arbitrary Python — только
  composе зарегистрированных анализаторов.

## Правила автономной работы

1. **Не коммитить без green pytest** на затронутых файлах.
2. **Один подэтап — один коммит.** Не сваливать в один PR.
3. **Каждый день начинать** с `git pull origin main` + `pytest -q`
   для baseline; если что-то красное — сначала fix.
4. **Каждый день заканчивать**:
   - `git push git@github.com:4stm4/BookAssembler.git main`,
   - обновить `docs/development/logs/YYYY-MM-DD.md`,
   - обновить `COMPLIANCE_AUDIT.md` если сдвинулись статусы.
5. **Тупики > 90 мин** без прогресса → `spawn_task` chip, продолжить
   со следующего пункта; не блокировать неделю на одном узле.
6. **`feedback_quality_over_speed`**: правильно, даже если сдвигает
   день. Отчёт объяснит.
7. **`feedback_no_local_install`**: любой pip/npm — Docker или
   одноразовый venv в scratchpad.
8. **`feedback_check_rfc`**: перед изменением кода — сверка с
   соответствующим RFC.
9. **Deploy через SSH**: rpi5 (primary), orangepi (secondary), rpi4
   (backup, когда вернётся). Все правки на удалённых хостах — через
   `docker compose` или systemd, никаких кастомных путей.

## Что вне плана недели (сдвинуто на сентябрь)

- **Corpus & Golden Set** для retrieval eval — нужен размеченный
  корпус на ≥ 100 книг; бонус среды даёт только harness + 20 пар.
- **Plugin marketplace UI** — sign/publish/browse через web-интерфейс;
  бонус четверга даёт CLI + API, UI строится в сентябрьской итерации.
- **Distributed KAE-инстансы (rpi5 + rpi4 mirror с автоматическим
  failover)** — понедельник ставит mirror вручную; авто-failover
  через HAProxy/Keepalived — отдельная неделя.
- **Возврат GPU-Runner (Kaggle или собственный GPU)** — код RFC 0022
  сохранён; активировать при появлении реального GPU-хоста.
- **NPU acceleration на RK3588 (orangepi)** через `rknn-toolkit2` —
  требует конверсии моделей и своего runtime, отдельный проект.
