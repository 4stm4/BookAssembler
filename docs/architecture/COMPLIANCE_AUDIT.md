# Аудит соответствия кода RFC 0001–0022

| Статус | Версия | Дата |
|---|---|---|
| Актуален | 0.2.0 | 2026-09-10 |

Сверка проведена по коду, а не по прошлым отчётам: для каждого RFC проверялось,
существует ли механизм и **вызывается ли он в рабочем пайплайне** — библиотека,
которую никто не зовёт, считается невыполненным требованием.

Статусы: ✅ соответствует · 🔧 частично · ➖ не реализовано.

## Что осталось

| Пробел | RFC | Почему не закрыт |
|---|---|---|
| DOCX/HTML/Notebook-адаптеры | 0008 §3.2–3.4 | новые подсистемы, объём сопоставим с PDF-адаптером |
| Загрузчик плагинов в рантайме анализаторов | 0010 | песочница готова; нужна точка расширения в пайплайне и решение о доверии |
| `ArtifactStore` / tiering L0–L3 | 0013 | развилка: подключать к рантайму или удалить как дубль `.kap`-пути |
| Пиннинг TeX Live и replay `kae rebuild` | 0012 §3.3, §4 | решение уровня деплоя (digest образа / snapshot.debian.org) |
| Merkle-деревья глав | 0011 §3.2 | нет потребителя |
| `ProfileResolver` в entry point | 0006 §4 | нужен продуктовый выбор, где автодетект издателя включается |

## Замечания по самим RFC

- **0015 §4 vs 0016 §1 vs 0017 §4** — три разных порога эскалации (WER/TEDS,
  confidence 0.80, полосы 0.85/0.60). В коде: HITL остаётся на 0.80 из 0016,
  ретрай vision — на 0.60 из 0017, дрейф — по 0015. Стоит свести в один документ.
- **0015 §3.1** — WER между оригиналом и переводом неинформативен (у корректного
  перевода он близок к 1.0). Реализовано как дрейф по защищённым токенам,
  которые перевод обязан сохранить без изменений.
- **0014** — буквальный `KAEAnalyzerContract` из текста RFC противоречит
  `BaseAnalyzer` из 0005; фактические контракты живут в `tests/contract`.
