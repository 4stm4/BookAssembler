# RFC 0002: Knowledge Representation Model (KRM)

| Статус | Версия | Дата | Автор |
|---|---|---|---|
| Draft | 1.0.0 | 2026-08-07 | Core Architecture Team |

## 1. Назначение и принципы KRM
Knowledge Representation Model (KRM) — это центральная структура данных ядра Knowledge Assembly Engine (KAE). Она служит единым источником правды (Single Source of Truth) для всех анализаторов, плагинов и экспортеров.

Ключевые принципы KRM:
- **Разделение слоев (Layer Separation):** Физические атрибуты верстки (координаты, шрифты, цвета) отделены от логической структуры и семантического смысла.
- **Строгая типизация (Strict Typing):** Запрещено использование универсальных узлов с флагами типа `node.type = "table"`. Каждый узел KRM представлен строго определенным классом данных.
- **Глобальная идентичность (Global Identity):** Каждый узел при создании получает UUIDv4 (`id`), который сохраняется неизменным на протяжении всего жизненного цикла объекта.
- **Безопасная модификация (Safe Mutation):** Связи и иерархия меняются только через явные методы интерфейса KRM или специализированные графы (Reading Graph, Knowledge Graph).

## 2. Иерархия классов KRM

```
KnowledgeDocument
 └── ContainerUnit (Chapter, Section, Subsection, Appendix)
      └── StructuralUnit (ParagraphBlock, TableBlock, FigureBlock, CodeBlock, FormulaBlock)
           └── SemanticUnit (InstructionSpec, DefinitionSpec, AlgorithmSpec, WarningSpec, NoteSpec)
                └── InlineUnit (TextLine, MathInline, CodeSpan)
                     └── SpanUnit (StyledText, EntityMention, FootnoteRef)
```

## 3. Спецификация слоев KRM
Модель KRM состоит из четырех связанных слоев:

```
┌─────────────────────────────────────────────────────────┐
│                 1. Semantic Layer                       │
│    (Knowledge Units: Instructions, Definitions, etc.)   │
└────────────────────────────┬────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────┐
│                 2. Structural Layer                     │
│    (Hierarchy: Document -> Container -> Block)          │
└────────────────────────────┬────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────┐
│              3. Visual Layout Layer                     │
│    (BBox, Fonts, Colors, Reading Order Bounding)        │
└────────────────────────────┬────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────┐
│                 4. Meta Layer                           │
│    (Provenance, Confidence, Hash, Source Info)          │
└─────────────────────────────────────────────────────────┘
```

### 3.1. Visual Layout Layer (Слой верстки)
Слой описывает геометрию и оформление элемента в источнике.

```python
from dataclasses import dataclass
from typing import Optional, Tuple

@dataclass(frozen=True)
class NormalizedRect:
    """
    Координаты прямоугольника, нормализованные относительно размеров страницы/экрана.
    Значения находятся в диапазоне [0.0, 1.0].
    """
    x0: float
    y0: float
    x1: float
    y1: float

    @property
    def width(self) -> float:
        return self.x1 - self.x0

    @property
    def height(self) -> float:
        return self.y1 - self.y0

@dataclass
class StyleDescriptor:
    font_family: str
    font_size_pt: float
    is_bold: bool
    is_italic: bool
    is_monospace: bool
    text_color_rgb: Tuple[int, int, int]
    background_color_rgb: Optional[Tuple[int, int, int]] = None

@dataclass
class VisualLayout:
    bounding_box: NormalizedRect
    page_or_screen_index: int
    style: Optional[StyleDescriptor] = None
    rotation_degrees: int = 0
```

### 3.2. Structural Layer (Структурный слой)
Слой задает базовое дерево документа.

#### Базовый узел KRM
```python
from abc import ABC
from dataclasses import dataclass, field
from uuid import uuid4, UUID
from typing import Optional, Dict, Any, List

@dataclass
class BaseKRMNode(ABC):
    id: str = field(default_factory=lambda: str(uuid4()))
    visual_layout: Optional[VisualLayout] = None
    confidence_score: float = 1.0
    is_tombstoned: bool = False
    metadata: Dict[str, Any] = field(default_factory=dict)
```

#### Элементы текста (Span & Inline)
```python
@dataclass
class SpanUnit(BaseKRMNode):
    text: str = ""

@dataclass
class StyledTextSpan(SpanUnit):
    pass

@dataclass
class EntityMentionSpan(SpanUnit):
    entity_id: Optional[str] = None
    entity_type: Optional[str] = None

@dataclass
class FootnoteRefSpan(SpanUnit):
    footnote_id: Optional[str] = None

@dataclass
class InlineUnit(BaseKRMNode):
    spans: List[SpanUnit] = field(default_factory=list)

@dataclass
class TextLineInline(InlineUnit):
    pass

@dataclass
class MathInline(InlineUnit):
    latex_code: str = ""
```

#### Блочные элементы (Structural Units)
```python
@dataclass
class StructuralUnit(BaseKRMNode, ABC):
    parent_container_id: Optional[str] = None

@dataclass
class ParagraphBlock(StructuralUnit):
    inlines: List[InlineUnit] = field(default_factory=list)

@dataclass
class TableCell(BaseKRMNode):
    row_span: int = 1
    col_span: int = 1
    content: List[StructuralUnit] = field(default_factory=list)

@dataclass
class TableBlock(StructuralUnit):
    grid: List[List[TableCell]] = field(default_factory=list)
    caption_id: Optional[str] = None

@dataclass
class FigureBlock(StructuralUnit):
    image_uri: Optional[str] = None
    mime_type: str = "image/png"
    caption_id: Optional[str] = None
    alt_text: Optional[str] = None

@dataclass
class CodeBlock(StructuralUnit):
    code_text: str = ""
    programming_language: Optional[str] = None
    has_line_numbers: bool = False

@dataclass
class FormulaBlock(StructuralUnit):
    latex_expression: str = ""
    is_numbered: bool = False
    formula_number: Optional[str] = None
```

#### Контейнеры (Containers)
```python
@dataclass
class ContainerUnit(BaseKRMNode):
    title: str = ""
    level: int = 1  # 1 = Chapter, 2 = Section, etc.
    children: List[BaseKRMNode] = field(default_factory=list)

@dataclass
class KnowledgeDocument(BaseKRMNode):
    title: str = ""
    source_uri: str = ""
    source_type: str = ""  # e.g., 'pdf', 'docx', 'html'
    root_containers: List[ContainerUnit] = field(default_factory=list)
```

### 3.3. Semantic Layer (Семантический слой / Knowledge Units)
Слой оборачивает структурные блоки, наделяя их прикладным смыслом для ИИ.

```python
@dataclass
class SemanticUnit(BaseKRMNode, ABC):
    target_block_id: str = ""  # Ссылка на StructuralUnit

@dataclass
class InstructionSpec(SemanticUnit):
    """Спецификация инструкции (например, процессорный опкод или API вызов)."""
    architecture_or_platform: str = ""
    mnemonic_or_function: str = ""
    operands_or_arguments: List[str] = field(default_factory=list)
    affected_flags_or_state: List[str] = field(default_factory=list)

@dataclass
class DefinitionSpec(SemanticUnit):
    """Определение термина."""
    term: str = ""
    definition_text: str = ""

@dataclass
class WarningSpec(SemanticUnit):
    """Предупреждение / Примечание по безопасности."""
    severity: str = "warning"  # 'info', 'warning', 'critical'
    message_text: str = ""
```

### 3.4. Meta Layer (Слой метаданных и происхождения)
Каждый узел содержательного контента хранит историю происхождения (Provenance):

```python
@dataclass
class ProvenanceInfo:
    adapter_name: str
    extraction_timestamp_utc: str
    source_byte_offset: Optional[Tuple[int, int]] = None
    applied_analyzers: List[str] = field(default_factory=list)
    applied_skills: List[str] = field(default_factory=list)
```

## 4. Инварианты KRM
Любое состояние `KnowledgeDocument` в системе должно удовлетворять следующим правилам:
1. **Единственность ID:** Не существует двух узлов в документе с одинаковым `id`.
2. **Отсутствие сирот (No Orphans):** Любой `StructuralUnit` должен входить в массив `children` ровно одного `ContainerUnit` либо быть явно связан через `ReadingGraph`.
3. **Валидность координат:** Поля `bounding_box` содержат значения от `0.0` до `1.0`. `x0 <= x1` и `y0 <= y1`.
4. **Неразрушимость текста:** Очистка от лигатур и нормализация переносов строк меняет только свойство `text` в `SpanUnit`, оставляя размерность массива `spans` непротиворечивой.
