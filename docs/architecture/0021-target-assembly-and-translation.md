# RFC 0021: Target Document Assembly & Translation

| Статус | Версия | Дата | Автор |
|---|---|---|---|
| Draft | 1.0.0 | 2026-08-18 | Core Architecture Team |

---

## 1. Назначение и концепция

RFC 0021 специфицирует **выходной слой** Knowledge Assembly Engine (KAE): перевод
размеченного `KnowledgeDocument` на целевой язык и сборку человекочитаемого
целевого документа (переведённая книга). До этого RFC процесс перевода и рендера
целевого документа не был описан: RFC 0012 покрывает воспроизводимость сборки,
RFC 0011 — происхождение, RFC 0013 — упаковку артефактов, но сам конвейер перевода
и правила восстановления вёрстки отсутствовали.

Слой сборки — это **экспортёр** в терминах RFC 0001 §3.3: он читает полностью
размеченный и валидированный KRM и **не запускает повторный анализ источника**.

### 1.1 Границы

- **Вход:** валидированный `KnowledgeDocument` + `ReadingGraph` + `KnowledgeGraph`.
- **Выход:** целевой документ (LaTeX → PDF по RFC 0012), упакованный в `.kap`
  (RFC 0013), с полной трассируемостью (RFC 0011).
- **Запрет мутаций KRM:** слой сборки **не изменяет** узлы KRM и не нарушает
  инварианты (RFC 0001 §2, RFC 0002 §4). Перевод создаёт **новые** узлы/сегменты
  с lineage-связью к исходным, а не переписывает исходный текст на месте.

## 2. Модель перевода

### 2.1 TranslatedSegment

Каждый переводимый текстовый узел KRM порождает переведённый сегмент, сохраняющий
привязку к оригиналу (RFC 0011):

```python
@dataclass
class TranslatedSegment:
    source_node_id: str          # UUIDv4 исходного узла KRM (не меняется, RFC 0001 §2.3)
    target_lang: str             # ISO 639-1, напр. "ru"
    source_text: str
    target_text: str
    bbox: BoundingBox            # проекция VisualLayout.bounding_box, [0,1] (RFC 0011 §2.1)
    lineage: LineageRecord       # source_sha256 + bbox + confidence (RFC 0011)
    transformation: TransformationStep  # agent_type, model, prompt_hash, output_hash
```

### 2.2 Детерминизм (наследуется из RFC 0012)

- Все LLM-вызовы перевода: `temperature = 0.0`, `seed = 42`.
- Промпты хэшируются (SHA-256), хэш пишется в `TransformationStep.prompt_hash`.
- Повторный прогон при попадании в CAS (RFC 0013) не вызывает LLM повторно.

### 2.3 Атомарные блоки

`CodeBlock`, `FormulaBlock`, `TableBlock`, `FigureBlock` **не переводятся построчно**
и не режутся (RFC 0007 §5.2). Код и формулы переносятся как есть; подписи
(`CaptionBlock`) переводятся отдельными сегментами.

## 3. Гибридный рендер вёрстки

Восстановление страницы целевого документа выбирается по роли страницы/блока:

| Класс страницы/блока | Стратегия рендера |
|---|---|
| Обычный текст (`ParagraphBlock`, заголовки) | **Reflow**: линейный поток LaTeX с сохранением уровня заголовка и выравнивания, выведенного из `bbox` (центр/лево/право). |
| Особые страницы: обложка (`page_role=cover`), титул/копирайт (`TitlePageBlock`), центрированные блоки | **Позиционный рендер**: текст размещается по нормализованному `bbox` (×размер страницы), с сохранением выравнивания и относительного размера шрифта из `StyleDescriptor`. |
| Скан-страницы без текстового слоя (`needs_ocr`, `BlankPageBlock`) | Переносятся как изображение исходной страницы (фон), поверх — переведённый текст по `bbox`, если он есть. |
| Атомарные блоки | Вставляются целиком, без переноса (RFC 0007 §5.2). |

Выравнивание выводится из `bbox`: блок считается центрированным, если
`|(x0 + x1)/2 − 0.5| < ε` и `x0 > δ`; правым — если `x1 ≈ 1 − δ` и `x0 > 0.5`.

## 4. Сборка (делегируется RFC 0012)

Рендер целевого документа обязан использовать **XeLaTeX** в locked Docker-образе
(`texlive:*-frozen`) и порождать `kae.lock` + `book.json` с `output_hashes`
(`krm_tree`, `knowledge_graph`, `latex_pdf`). Собранный PDF и промежуточные
артефакты помещаются в content-addressed `.kap` bundle (RFC 0013).

---

## 5. Инварианты слоя сборки

1. **Неизменность источника:** сборка не мутирует KRM; перевод создаёт новые
   сегменты со ссылкой на `source_node_id` (RFC 0001 §2.3, §2.4).
2. **Полнота трассировки:** каждый `TranslatedSegment` имеет `LineageRecord` и
   `TransformationStep` (RFC 0011); сегмент без lineage недопустим.
3. **Детерминизм:** повторная сборка того же входа с тем же `kae.lock` даёт
   byte-identical PDF (RFC 0012).
4. **Сохранение геометрии:** `bbox` и `StyleDescriptor` каждого исходного узла
   доступны сборщику (round-trip persist по RFC 0002); зануление координат
   при сериализации запрещено.
