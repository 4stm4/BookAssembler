# Стенд оглавлений (TOC bench)

Регрессионный стенд для чтения печатного оглавления (RFC 0009): десять
разных книг, по каждой — эталон, сверенный вручную с напечатанной страницей.
Цель — один в один на всех книгах.

## Что сверяется

Для каждой книги `bench.py` прогоняет пайплайн до `BlockClassifierAnalyzer`
и проверяет четыре вещи:

| проверка | что значит «верно» |
|---|---|
| **titles** | номер + заголовок каждой записи, по порядку, как напечатаны |
| **pages** | ссылка на страницу, как напечатана («45», «xiii», «2-15») |
| **targets** | на странице, куда ведёт запись (`target_page`), напечатан этот колонтитул; у страницы без колонтитула — соседние колонтитулы вокруг неё |
| **outline** | у книг с осмысленным оглавлением PDF — `target_page` совпадает со страницей того же раздела в outline |

Колонтитулы и outline читаются PyMuPDF прямо из PDF, мимо проверяемых
анализаторов. Книга засчитывается как `EXACT`, только если сошлись все
четыре; код выхода 0 — только если `EXACT` все книги.

## Корпус

Самих книг в репозитории нет: это чужие издания под авторским правом,
десятки мегабайт. `corpus.json` закрепляет каждое издание по sha256 и
указывает, откуда оно взято; при другом sha256 стенд книгу не засчитает.

| книга | что это | трудность |
|---|---|---|
| `buildroot` | Buildroot user manual 2026.02.1 | 234 записи, многоуровневое |
| `intel3000` | Intel Series 3000 Reference Manual, 1976 | скан с текстовым слоем |
| `mcs40` | Intel MCS-40 User's Manual, 1974 | скан, две колонки, нет заголовка, строки без страницы — описания |
| `mpman-ru` | MetaPost, русский перевод | кириллица, две колонки |
| `readline` | GNU Readline Library 8.3 | оглавление на двух страницах, уровни |
| `sbc6120` | SBC6120 User's Manual | уровни |
| `signetics8080` | Signetics 8080 Emulator Manual, 1977 | скан, OCR с ошибками |
| `texlive-ru` | TeX Live, руководство | кириллица |
| `z80` | Zilog Z80 CPU User Manual UM0080 | 218 записей |
| `zaks-z80` | R. Zaks, Programming the Z80, 3rd ed. | OCR OmniPage («II.» читается как «H.»), темы глав — описания |

На rpi5 все десять лежат под бенчевыми именами в `/home/alex/toc-dev/books/`
(`<книга>.pdf`); исходные пути — в поле `origin` в `corpus.json`.

## Запуск

Только на rpi5, в образе движка (в нём есть PyMuPDF), из копии репозитория:

```bash
docker run --rm --user $(id -u):$(id -g) \
  -v $PWD/src:/app/src:ro -v $PWD/benchmark:/app/benchmark:ro \
  -v /home/alex/toc-dev/books:/books:ro -w /app \
  bookassembler-kae python3 -m benchmark.toc.bench --books /books
```

Отдельные книги — именами после опций; `--out DIR` пишет прочитанные записи
(`text`, `page_label`, `level`, `target_page`, `src_page`, `description`)
в `DIR/<книга>.json`.

Тот же стенд — тестом, если задан `KAE_TOC_BOOKS` (без него тест
пропускается):

```bash
docker run --rm --user $(id -u):$(id -g) -e KAE_DATA_DIR=/tmp/kae -e KAE_TOC_BOOKS=/books \
  -v $PWD/src:/app/src:ro -v $PWD/benchmark:/app/benchmark:ro -v $PWD/tests:/app/tests:ro \
  -v /home/alex/toc-dev/books:/books:ro -w /app \
  kae-test python3 -m pytest -q tests/integration/test_toc_bench.py
```

Ожидаемо: `EXACT 10/10`, 812 записей, все цели подтверждены колонтитулами,
в outline ни одного расхождения.

Разбор, почему страница прочиталась не так: колонки, ряды, записи и
описания по страницам (номера страниц физические, с нуля):

```bash
... bookassembler-kae python3 -m benchmark.toc.debug --books /books zaks-z80 6,7,8
```

## Эталоны

`gt/<книга>.json` — `{"source": "...", "entries": [{"text", "page"}, ...]}`:

- `text` — номер и заголовок, как напечатаны; `page` — ссылка, как
  напечатана; `level` — где уровень виден в вёрстке.
- В эталон входят только строки со ссылкой на страницу. Строки без
  страницы — описания предыдущей записи (MCS-40, темы глав у Закса).
- Ошибки текстового слоя, которые на странице не видны, в эталоне
  исправлены по напечатанному (у Закса «II.», а не «H.»); остальные
  сохранены как есть (Signetics) — поле `source` каждого файла говорит,
  что откуда.

Правка эталона — только с объяснением в коммите (RFC 0009 §5.1): эталон
описывает книгу, а не вывод пайплайна, и под вывод его не подгоняют.

Новая книга: положить PDF к остальным, добавить её в `corpus.json` с
sha256, собрать черновик эталона и **проверить его построчно по странице**:

```bash
... bookassembler-kae python3 -m benchmark.toc.draft_gt /books/<книга>.pdf <первая> <последняя>
```

Черновик строится независимо от анализаторов (слова PyMuPDF, регулярное
выражение на ссылку в конце строки) и сверяется с outline, если он есть.
